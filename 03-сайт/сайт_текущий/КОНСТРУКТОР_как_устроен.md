# Конструктор страниц — как устроен и как его править

Файл: `сайт_текущий/constructor-v5.html` (54 КБ, версия **v7.5**, весь код внутри одного файла — HTML + CSS + JS, без зависимостей).
Живёт по адресу `https://zapahstarosti.ru/constructor-v5.html`.
Вход: `https://zapahstarosti.ru/?admin=1` → в меню появляется пункт «Конструктор» (ставится флаг `localStorage.isAdmin='1'`).

**Зачем он:** Инна правит страницы сама, из браузера, без git. Конструктор загружает страницу с сайта, даёт визуальный редактор, пересобирает HTML и коммитит его в GitHub через API. Поэтому **перед любой правкой страницы всегда тянуть свежее состояние из репозитория** — локальная копия может отстать от того, что Инна уже наредактировала.

---

## 1. Ключевая архитектурная идея (не сломать!)

Есть два принципиально разных пути сборки — их выбирает `buildHtml(slug)`:

| Функция | Когда вызывается | Что делает |
|---|---|---|
| `buildFromOriginal(slug)` | Страница уже существует (загружена с сайта) | **Не пересобирает по шаблону.** Берёт собственный HTML страницы, парсит DOMParser'ом и точечно заменяет: `<title>`, `meta description`, `canonical`, содержимое `.content`. Меню, favicon, метрика, верификация, noindex, og, ld+json остаются ровно как были |
| `buildNewPage(slug)` | Страницы нет, создаётся с нуля | Собирает из шаблонных констант `FULL_NAV`, `METRIKA_HEAD`, `DROPDOWN_JS` + генерирует OG-теги и JSON-LD |

⚠️ **Это главное исправление v7.** Раньше правка существующей страницы пересобирала её по шаблону и затирала уникальные og-картинки и разметку. Не возвращать пересборку по шаблону для существующих страниц.

## 2. Три бага, которые уже чинили — не повторять

**v7.4 — Метрика и DOMParser.** Блок Яндекс.Метрики вырезается из HTML *до* парсинга и подставляется обратно после:
```js
var MO='<!-- Yandex.Metrika counter -->', MC='<!-- /Yandex.Metrika counter -->';
// вырезать → '<!--ZAPMETRIKA-->' → парсить → вернуть эталонный блок
```
Причина: DOMParser без исполнения скриптов выбрасывает `<div>` из `<noscript>` в `<body>`. Пиксель начинает грузиться у всех, визиты считаются вдвое. **Если тронете этот участок — сломаете статистику.**

**v7.2 — один H1.** Что видно в редакторе, то и сохраняется. Если в теле несколько `<h1>` — остаётся первый, остальные удаляются. Если нет ни одного — подставляется из поля `h1`.

**v7.5 — OG и JSON-LD для новых страниц.** Новая страница получает og:image `images/og/home.jpg` (общая, всегда существует). Уникальную карточку надо сгенерировать отдельно и поправить `og:image` руками.

## 3. Карта функций

| Функция | Что делает |
|---|---|
| `lsGet/lsSet/lsDel`, `tokenStatus` | Хранение и индикация GitHub-токена в localStorage |
| `buildFromOriginal` / `buildNewPage` / `buildHtml` | Сборка HTML (см. выше) |
| `save()` | `PUT` в GitHub Contents API, нужен `sha` текущего файла |
| `download()` | Скачать собранный HTML файлом, без коммита |
| `sanitizeHtml`, `cleanPastedHtml`, `insertClean` | Чистка HTML: своего и вставленного из Word/браузера |
| `exec`, `applyStyle`, `applySize`, `wrapSelectionInSpan` | Команды редактора |
| `addLink`/`openLinkModal`/`insertLink`, `addAnchor`, `addColor`, `addTable`, `addNote`, `addKstati`, `addButton`, `addImg` | Вставка элементов. `addNote`/`addKstati` дают врезки с классами `.note` / `.kstati` |
| `compressImage`, `pickImgFromDevice`, `autoImgName` | Загрузка картинки с устройства со сжатием и автоименованием |
| `saveSel`/`restoreSel`, `currentBlock` | Работа с выделением |

## 4. Поля интерфейса (id элементов)

`owner`, `repo`, `branch`, `token`, `tokenEye`, `tokenStatus`, `remember` — доступ к GitHub.
`slug`, `newSlug`, `title`, `desc`, `h1`, `noindexBox` — метаданные страницы.
`editor` — само поле редактирования (contenteditable).
`styleSel`, `sizeSel`, `colorPicker`, `imgFile`, `linkModal`/`linkUrl`/`linkText`/`linkArticle`, `status`, `envNote`, `adminLink`, `__paste`.

## 5. Токен GitHub

Fine-grained, права **Contents: Read and write** только на репозиторий `zapahstarosti`. Вводится один раз в браузере Инны, лежит в localStorage. В коде токена нет.

## 6. Регламент правки конструктора

1. Правите — **обязательно поднимите номер версии** (он выводится в интерфейсе и проверяется curl'ом).
2. Прогоните тесты:
   ```bash
   npm i jsdom && CONSTRUCTOR_FILE=fix4/constructor-v5.html node qa/constructor-test-v74.js
   ```
   41 проверка на jsdom. **Гонять при любой правке.**
   ⚠️ Папки `qa/` в этом пакете нет — она лежит в рабочем репозитории `ooppanki2021-hash/zapahstarosti`. Возьмите оттуда.
3. Проверка после заливки:
   ```bash
   curl -s "https://zapahstarosti.ru/constructor-v5.html?v=751" | grep -o "v7.5"
   ```
4. Предупредить Инну: **давно открытую вкладку конструктора надо перезагрузить**, иначе работает старый код из кеша.
5. Перед кнопкой «Сохранить на сайт» — проверять галочку `noindex`. Случайно снятая галочка открывает сырую страницу в поиск.
