# Приложение «Шаги к мечте» — техописание

Личный трекер Инны. Путь от текущего состояния до собственной производственной линии, разбитый на шаги и конкретные действия.

**Где живёт:** `https://zapahstarosti.ru/app/` · в этом пакете — `app/`
**Код входа:** `0820`
**Автономная копия:** `МЕЧТА_автономная_копия.html` — тот же файл целиком, работает с флешки без интернета.

---

## 2. Хранение данных

Решение принято сознательно («третий путь»): **никакого сервера и никакого облака.**

**Перенос дела на другой день** — два способа, оба под значком `⋯` справа от дела:
- `bumpTask(id, days)` — кнопки «На завтра» (+1), «На неделю вперёд» (+7), «На день назад» (−1). Сдвиг считается **от собственной даты дела**, через `Date.UTC(...,12,0,0)` — полдень по UTC, чтобы переход на летнее/зимнее время не съедал и не добавлял сутки. Проверено на конце месяца, Новом годе и високосном феврале.
- `moveTask(id, iso)` — календарик с конкретной датой.
После переноса блок `⋯` закрывается и всплывает подтверждение (`toast`).

- Всё лежит в `localStorage`, ключ **`dubrava_dream_v1`**, один JSON-объект.
- Резервная копия — вкладка «Данные» → экспорт в файл `мечта-состояние-YYYY-MM-DD.json`, импорт оттуда же.
- Значит: чистка кеша браузера = потеря данных. **Предупреждать про регулярный экспорт.**

## 3. Вход по коду

```js
const PIN_DEFAULT_HASH = '25d74826';
```
`pinHash()` — двойной FNV, результат 8 hex-символов. **Самого кода в файле нет**, только хеш.
Забытый код лечится подменой константы на новый хеш — **данные при этом не теряются**.
Функции: `initLock`, `tryPin`, `unlock`, `changePin`, `currentHash`.

## 5. Структура пути

```js
const DEFAULT_MILES = [
  { n: "ШАГ 1. …",            // название
    d: "2–3 нед · 0 ₽",       // срок и деньги
    done: false,
    why: "Зачем этот шаг — 2–4 предложения простым языком",
    sub: [ {t:"действие", done:false}, … ] }
]
```

**Поле `why`** выводится блоком «Зачем этот шаг» вверху раскрытого шага (класс `.why`, охряная полоса слева). Обязательно у всех 20 шагов.

⚠️ **Язык текстов — отдельное требование Инны.** Никаких терминов без расшифровки: не «SKU», а «продукт»; не «СГР», а «свидетельство о госрегистрации — разрешение продавать бытовую химию»; не «ретробонус», а «скидка сети»; не «FBO», а «хранение на складе площадки»; не «noindex», а «запрет на показ в поиске». Если термин нужен — объяснять прямо в той же строке. Это касается и `DEFAULT_TASKS`.

**Обновление текстов у пользователя.** Тексты живут в `localStorage`, поэтому правка `DEFAULT_MILES` сама по себе до пользователя НЕ доедет. Механизм:
```js
const MILES_TEXT_VERSION = 2;   // поднять при правке формулировок
function refreshMileTexts(){ … } // вызывается в load() после migrate()
```
Функция переписывает `n`, `d`, `why` и тексты подшагов **по позиции в массиве**, не трогая отметки `done`, задачи и заметки. Поднял версию — тексты обновились у всех. **Если меняется число или порядок шагов — сверка по позиции сломается**, тогда правьте `migrate()`, а не эту функцию.
20 шагов, 154 действия, 19 уже отмечены закрытыми. Порядок шагов **не случаен** — обоснование в `../01_НАЧНИ_ОТСЮДА/ПОЛНОЕ_ДОСЬЕ.md`, часть 9:
- шаг 13 (продукт доказал себя) — строго перед 14 и 18;
- шаг 14 (корпоративный клиент) — перед 18: нужен отзыв на бланке юрлица;
- шаг 17 (маркетплейсы) — перед 18: сети требуют рейтинги продаж по регионам;
- шаг 19 (своя линия) — последним.

## 6. ⚠️ Функция `migrate()` — не удалять

Вызывается внутри `load()`. Переносит сохранения, сделанные до появления подшагов: сопоставляет старые вехи с новыми шагами **по имени**, отсекая префикс `ШАГ N. `. Сохраняет отметки, заметки и задачи.
Без неё у Инны при обновлении приложения обнулится весь прогресс. Уже был такой баг — починен, не откатывать.

## 7. Как добавить или изменить шаг

1. Найти `const DEFAULT_MILES` в `index.html`.
2. Добавить/изменить объект. Поля `n`, `d`, `done`, `sub` — обязательны у **каждого** шага (пустой `sub: []` допустим, отсутствующий — нет, сломает рендер).
3. **Название менять осторожно** — `migrate()` сопоставляет по имени. Переименовали шаг — у Инны слетит отметка по нему. Если меняете только формулировки, не трогая количество шагов, — поднимите `MILES_TEXT_VERSION`, этого достаточно.
   Добавили шаг — обязательно с полем `why`.
4. Проверить синтаксис:
   ```bash
   node -e "new Function(require('fs').readFileSync('app/index.html','utf8').match(/<script>([\s\S]*)<\/script>/)[1])"
   ```
5. Скопировать в автономную версию: `cp app/index.html МЕЧТА_автономная_копия.html`.
6. Залить `app/` в репозиторий сайта.
7. **Сказать Инне нажать Ctrl+F5** — service worker кеширует агрессивно. Если правки не видны — поднять версию кеша в `sw.js` (`mechta-v2` → `mechta-v3`).

## 9. Требования, которые ставила Инна (выполнены, не откатывать)

- Работать **не в браузере, а как приложение** → PWA с установкой на рабочий стол.
- **Тёмная тема.**
- На главном экране **и** дело дня, **и** полоса прогресса.
- Календарь **редактируемый**.
- Заметка к делу, перенос дел, повторяющиеся дела — все три.
- Вход по коду.
- Данные — локально + выгрузка файлом.

Инструкция для пользователя (установка на ПК / Android / iPhone) — в `УСТАНОВКА_приложения.md`. На iPhone работает **только через Safari**.
