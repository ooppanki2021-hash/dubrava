PIN — удобство, не шифрование. При восстановлении сначала сохранить резервную копию; замена константы не обязательно изменит уже сохранённый пользовательский хеш. Личные заметки и отметки не загружаются в репозиторий автоматически.

## Структура данных

Хранится в `localStorage` браузера, ключ `dubrava_dream_v1`:

```js
{
  tasks: [{id, d:'2026-09-15', t:'текст', n:'заметка', tag, rep, done}],
  miles: [{id, n:'название шага', d:'время и деньги', done, sub:[{t, done}]}],
  notes: [{id, date, text}]
}
```

**Путь из 20 шагов** зашит в константу `DEFAULT_MILES` в `index.html`. Подсчитано **153 поддействия**. Тексты и начальные отметки — шаблон плана, не данные из браузера автора. Менять только с сохранением миграции и после согласования.

⚠️ При изменении структуры `DEFAULT_MILES` работает функция `migrate()` — она переносит старые отметки на новые шаги по совпадению названий. Не удалять её.

## Как Инна передаёт своё состояние

Вкладка «Данные» → «Выгрузить состояние» → JSON-файл. По нему видно, что сделано и где она застряла.

## Известное ограничение

Локально воспроизведён сценарий неполного сброса: вложенные подшаги нового состояния разделяют объекты с `DEFAULT_MILES`. Код не исправлялся в рамках синхронизации документов. Не сбрасывать данные для обновления программы. Старые юридические/финансовые формулировки плана не заменяют уточнения постоянного резюме.
